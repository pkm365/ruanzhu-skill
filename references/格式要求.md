# 软著鉴别材料格式要求（某软件公司 2026.8 实操规范整理）

来源：《软著申请材料文档格式 2026.8》+ 2024.7 操作手册实操要求+ 申请表参考模板顶部说明。
以下全部为**硬性规则**，脚本已内置，但人工交付前仍需逐条核对。

## 一、源代码（程序鉴别材料）

| 项 | 要求 |
|---|---|
| 页数 | 超 60 页：**连续**前 30 页 + **连续**后 30 页；不足 60 页：全部提交，不删不重复 |
| 首页 | 必须是程序起始部分（main()、入口、登录页、index 文件），不能从中间截 |
| 尾页 | 必须是程序结束部分（完整模块收尾），不能半截函数/半截括号 |
| 每页行数 | **严格 50 行纯代码**，空行、纯注释不计入；结束页不足 50 行时页底标注"本页为源代码最后一页，共 XX 行" |
| 页码 | 每页标页码，建议右上角；前 30 页 1–30，后 30 页 31–60，连续不跳不重 |
| 页眉 | 每页"软件全称+版本号"（如 XX管理系统V1.0），与申请表、手册**完全一致** |
| 内容 | 删第三方库、配置文件、大量空行，保留核心原创代码；无乱码、无遮挡、无水印 |
| 语言 | 源码中出现的所有编程语言都要填进申请表"编程语言" |
| 格式 | Word 文档 |

已过审代码文档实际排版：A4，边距上 1.8 / 下 1.6 / 左右 2.4 cm，宋体 9pt，每 50 行一个 `pageBreakBefore`，全文 3000 段 = 60 页 × 50 行，零空行；页眉左"软件全称V1.0"，右侧框架"第 N 页"。

## 二、说明书 / 操作手册（文档鉴别材料）

| 项 | 要求 |
|---|---|
| 页数 | 连续前 30 + 后 30；不足 60 页交全部；**除目录外不少于 20 页**（实操必须）；申请表说明写不少于 15 页 |
| 每页行数 | 文字不少于 30 行（有图页除外）；**每页不能全是图** |
| 页眉 | "软件全称+版本号"，与申请表完全一致 |
| 页码 | 每页标页码，建议右上角 |
| 内容 | 图文并茂：封面、目录、功能说明、操作流程、运行环境、界面截图；每张图附说明文字 |
| 截图 | 完整系统截图，**含标题栏、功能栏、菜单栏、关闭/退出按钮**，能看出功能跳转；清晰无马赛克，建议 ≥300dpi |
| 截图-标题栏 | 手册截图中的系统标题栏名称必须与申报名称相符；关键位置不能打码；客户 logo 可 P 掉或打码 |
| 截图-马赛克 | 封盖内容不能太多，否则高概率补正；只有客户 logo 允许打码 |
| 截图-建议 | 截图时浏览器只开本软件相关页面，关闭无关标签页 |
| 建议 | 增加登录界面、主界面展示 |
| 禁止出现 | 硬件安装组装说明；硬件结构说明；**功能函数代码**；指数参数表格 |
| 格式 | Word 文档 |

已过审操作手册实际排版：A4，边距上下 2.54 / 左右 3.175 cm，宋体 12pt，Heading 1/2 分章，封面四行（软件全称 / 操作手册 / 著作权人 / 版本），Word 目录，页眉"软件全称V1.0"。该范例**没有页码**——脚本已补上（右上角）。

## 三、申请表

- 除"软件简称"外全部必填；一经录入系统无法修改。
- 主要功能：**500–1300 字**，禁止通用模板空话；必须写明研发背景、系统架构、各功能模块、技术实现方式、业务应用场景。审核系统自动校验"功能描述 ↔ 源代码 ↔ 用户手册"三者一致性，不匹配直接补正/驳回。
- 技术特点：100 字以内。
- 源程序量：真实统计行数。
- 权利人名称、证件号码：与版权中心实名认证信息完全一致。

## 四、一致性通用要求

- 源代码、说明书、申请表三处的软件名称、版本号、权利人信息**必须完全一致**；"V1.0" 与 "1.0" 都算不一致。
- 单个 PDF 建议 10–50 MB。
- 已知反例：某已提交材料的手册封面著作权人写"XX信息技术有限公司"，申请表写"XX智能科技有限公司"，这就是典型的会被补正的错误。
