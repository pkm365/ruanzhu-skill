# 操作手册写作规范

读者是版权中心审核员和最终用户，不是开发者。目标：让审核员看完能相信"这个软件真实存在、功能与申请表描述一致、截图与文字对应"。

## 结构（已过审范例风格，按真实菜单分章）

```
封面：软件全称 / 操作手册 / 著作权人 / 版本          ← 脚本自动生成
目录                                               ← 脚本自动生成
1 软件概述
  1.1 简介（1 段：给谁用、解决什么问题、主流程一句话）
  1.2 功能特点（连贯段落，对应申请表"主要功能"里的模块）
  1.3 运行环境（表格：操作系统 / 浏览器 / 数据库 / 硬件，与申请表一致）
2 系统登录（登录页截图 + 主界面截图，实操要求建议必有）
3..N 各功能模块（按左侧菜单顺序，一级标题 = 菜单名）
  N.1 子功能（二级标题 = 子菜单/页签名）
    功能描述：一段话说这个页面干什么
    操作步骤：1. 从哪进入 2. 看到什么 3. 怎么操作 4. 输入限制 5. 结果/提示
    截图 + 图注（图 N-x 页面名称）
N+1 常见问题（可选，3–8 条问答，能凑正文行数）
```

也可用"一、相关文档 … 七、术语表"的通用结构，但已过审材料用的是上面这种，优先沿用。

## 篇幅硬指标

- 除目录外 ≥20 页；每页文字 ≥30 行（有图页除外）；**每页不能全是图** → 每张截图前后都要有文字。
- 经验值：15–25 张截图 + 8000–12000 字正文 ≈ 25–30 页。
- 截图密度：一个二级小节 1–3 张，每张必须有说明文字，图注写"图 N-x ××页面"。

## 截图规则（实操必须）

1. 完整窗口：含浏览器标题栏/标签栏、系统顶栏、菜单栏、关闭按钮，能看出功能跳转。
2. 标题栏里的系统名称必须与申报全称相符；截图前只开本系统页面，关掉无关标签。
3. 只允许对客户 logo 打码，其余任何位置不打码；打码面积大会补正。
4. 清晰、无水印、无遮挡；分辨率 ≥300dpi 或原始屏幕分辨率。
5. 登录页 + 主界面必须有。
6. 截图文件放 `草稿/截图/`，命名 `NN-页面名.png`，Markdown 里用 `![图 N-x 页面名](截图/NN-页面名.png)` 引用。

## 措辞

- 写页面、按钮、字段、结果；不写框架名（Vue/Spring）、接口、状态管理、数据库表、异步任务。
- 禁止贴任何代码片段（说明书禁止"功能函数代码"）。
- 禁用空话：赋能、一站式、智能化、高效便捷、旨在、全方位、打造、深度融合。
- 正文用连贯段落，操作步骤用"1. 2. 3."编号句，少用项目符号堆砌。
- 模块名、按钮名与系统界面上的文字一字不差；一级标题与申请表"主要功能"中提到的模块名一致。

## 没截图时

保留醒目占位 `【截图预留：请插入「××页面」截图。】`，脚本会渲染成红色加粗；`check_consistency.py` 会拦截未替换的占位。
